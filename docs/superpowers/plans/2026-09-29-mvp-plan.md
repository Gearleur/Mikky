# Mikky — MVP, partie A : plan d'implémentation

Date : 2026-09-29 · Spec : [../specs/2026-09-29-mvp-design.md](../specs/2026-09-29-mvp-design.md)

Partie A = brancher Claude et Codex (par ACP, comme Paperclip) et la petite fenêtre à droite. Chaque jalon se termine par les tests, une vérification (visuelle pour l'UI : goldens, puis relancer l'app et regarder), et un commit ; on pousse sur GitHub en fin de journée. Le jalon en cours est détaillé ; les suivants le seront au moment de les commencer.

## A0 · Essai : ACP, Windows, WSL (faisabilité)

But : vérifier, avant d'écrire le vrai code, que tout ce que la spec attend d'ACP marche avec nos outils, sous Windows et dans WSL, et enregistrer de vraies sessions pour les tests. Rien dans l'app pour l'instant.

1. **Adaptateurs** : installer `@agentclientprotocol/claude-agent-acp` et `@agentclientprotocol/codex-acp` avec npm dans un dossier d'essai, sous Windows (Node 24) et dans WSL (Node 18 : voir s'ils démarrent ; sinon, **demander à l'utilisateur** avant d'installer Node 24 dans WSL).
2. **Codex dans WSL** : `codex login --device-auth` ; l'utilisateur se connecte avec le lien et le code (c'est aussi l'essai du futur écran de connexion).
3. **Sonde ACP** : un petit script Dart (`packages/mikky_agents/tool/acp_probe.dart`) qui lance un adaptateur (directement ou par `wsl.exe`), fait `initialize`, `session/new` dans un dossier jetable, affiche les modes proposés, envoie une consigne simple (« liste les fichiers, fais un plan en 3 étapes, crée hello.txt, lance `ls` »), écrit chaque message reçu dans un fichier `.jsonl`, et pose les demandes de permission dans la console.
4. **À vérifier pour chaque agent (Claude, Codex) et chaque cible (Windows, WSL)** :
   - la demande de permission arrive en mode « Demander » et attend la réponse ; oui et non marchent ;
   - quel mode donne « Auto » (Claude : `auto` ; Codex : revue automatique) et qu'il ne demande plus rien ;
   - les mises à jour : texte, appels d'outils (genre, état, commande), **plan**, **diff** ;
   - un message envoyé pendant un tour : file d'attente ou arrêt du tour ;
   - `session/load` reprend une session, y compris une session lancée hors de Mikky ;
   - `session/cancel`, puis arrêt du processus et de tous ses enfants (job object sous Windows, groupe de processus dans WSL) ;
   - la session apparaît bien dans `~/.claude/projects` / `~/.codex/sessions` avec le même id.
5. **Sessions de WSL vues de Windows** : `Directory.watch` de Dart sur `\\wsl.localhost\Ubuntu\home\gearleur\.claude\projects` reçoit-il les changements ? Sinon, essai d'une sonde `inotifywait` lancée par `wsl.exe` qui écrit une ligne par changement.
6. **Enregistrements** : garder 2 ou 3 sessions par agent (flux ACP + fichiers de session), nettoyées de tout contenu privé, dans `packages/mikky_engine/test/fixtures/` pour A1.
7. **Résultat** noté ici, avec les points qui changent la spec. **Point avec l'utilisateur avant A1.**

Si ACP bloque sur un point (par exemple les permissions de Codex), on passe ce point par le secours en ligne de commande (spec §3.2) et on le dit à l'utilisateur.

**Résultat (2026-09-29) : faisabilité validée, Claude et Codex, sous Windows et dans WSL.** Sonde : `packages/mikky_agents/tool/acp_probe.dart` (et `watch_probe.dart`).

| | Claude Windows | Claude WSL | Codex Windows | Codex WSL |
|---|---|---|---|---|
| Lancement par ACP, lecture en direct | oui | oui | oui | oui |
| Demande de permission, Oui / Non | oui | oui | oui | oui |
| Plan (ligne de métro) | oui (TaskCreate / TaskUpdate → `plan`) | oui | pas vu (le modèle n'a pas pris l'outil) | pas vu |
| Message glissé pendant le travail | oui (file d'attente) | oui | oui | oui |
| Arrêt (`session/cancel`) et plus aucun processus ensuite | oui | oui | oui | non essayé, même chemin |
| `session/list` et `session/load` | oui, y compris les sessions de VS Code | — | annoncés | — |

Ce qu'on a appris (à reprendre dans A2) :
- **Adaptateurs** : `claude-agent-acp` 0.84 (demande Node ≥ 22 ; `CLAUDE_CODE_EXECUTABLE` pour lancer le `claude` de l'utilisateur) et `codex-acp` 2.0 (enveloppe `codex app-server` ; embarque son propre `codex` 0.158, `CODEX_PATH` pour un autre). Les deux utilisent la connexion de l'utilisateur (`~/.claude`, `~/.codex/auth.json`).
- **Node** : Windows a Node 24. Dans WSL, **Node privé de Mikky** (choix de l'utilisateur) : Node 24.19 dans `~/.local/share/mikky/node`, adaptateurs dans `~/.local/share/mikky/acp`. Le Node 18 d'Ubuntu n'est pas touché.
- **Modes Claude** : `default` (Manual), `acceptEdits`, `plan`, `auto`, `bypassPermissions`. Demander = `default`, Auto = `auto`. **Auto dépend du modèle** : avec Haiku, Claude refuse et passe en `acceptEdits` (« Auto mode unavailable ») ; avec le modèle par défaut, Auto marche. Mikky affiche le mode réel (`current_mode_update`).
- **Modes Codex** : `read-only` (demande avant toute modification), `workspace-write`, `agent` (« Auto review », **par défaut**), `agent-full-access`. Demander = `read-only`, Auto = `agent`. Jamais `agent-full-access`.
- **Codex : « Non » arrête tout le tour** (l'option de refus est `cancel`) : l'utilisateur écrit ensuite ce qu'il veut à la place. Claude, lui, continue avec l'étape suivante.
- **Message glissé** : Claude répond tout de suite au premier prompt (fin de tour vide) et termine le vrai tour sur le second ; Codex ne répond jamais au premier. Règle : le tour finit quand le dernier prompt répond.
- **Sessions de WSL vues de Windows** : `Directory.watch` sur `\\wsl.localhost\…` ne reçoit **aucun** événement. La sonde marche : un petit script lancé avec le Node privé dans WSL (`fs.watch` récursif, inotify), une ligne JSON par changement ; elle s'arrête avec `wsl.exe`.
- **Connexion de Codex dans WSL** (`codex login --device-auth`) : il faut un pseudo-terminal (`script -q -f -c …`) ; un premier essai a échoué sur une erreur réseau pendant l'attente, le second a marché. Mikky doit savoir relancer.
- Titre de session : Claude et Codex l'envoient (`session_info_update`).

## A2 · `packages/mikky_agents` (Dart + `dart:io`, sans Flutter)

**Fait (2026-09-29).** `lib/src/` :
- `target.dart` : lancer sous Windows ou dans WSL (`bash -l`, chemins dans les deux sens, cible déduite du dossier), arrêter tout l'arbre de processus. `job.dart` : chaque agent dans son **job object** Windows (ajouté à la demande de l'utilisateur) : l'arrêter arrête tout ce qu'il a lancé, et si Mikky se ferme, Windows arrête ses agents avec lui ; `taskkill /T` seulement si Windows refuse le job. Dans WSL, le job contient `wsl.exe`, dont l'arrêt arrête l'agent (vu en A0).
- `acp/acp_connection.dart` (JSON-RPC ligne par ligne) et `acp/agent_run.dart` : ouvrir ou reprendre une session, mode de permission (`modeFor`), modèle (`setModel` : `session/set_model`, ou l'option de configuration `model` de Claude), messages et messages glissés, Oui / Non, arrêt du tour, arrêt complet. `offeredModels` écarte Haiku.
- `setup.dart` : le dossier de Mikky par cible (`%LOCALAPPDATA%\Mikky`, `~/.local/share/mikky`), vérification (Node ≥ 22, adaptateurs, sonde WSL), installation (versions épinglées d'A0 ; Node privé vérifié par SHA-256 dans WSL), le `claude` de l'utilisateur donné à l'adaptateur.
- `auth.dart` : `claude auth status`, `codex login status`, connexion (`codex login --device-auth` sous `script` dans WSL, `claude auth login`), lien et code lus dans la sortie sans la garder.
- `watch/session_watcher.dart` : fichiers récents lus au départ, puis suivis (Windows : `Directory.watch` ; WSL : la sonde), lecture incrémentale même au milieu d'une ligne.
- `store.dart` : `agents.json` (agents de Mikky, dossiers récents, derniers choix par dossier), sauvegardes l'une après l'autre, fichier cassé mis de côté.
- `real_source.dart` : `RealAgentSource` (même `AgentSource` que la démo, plus `changes`) : lancer, reprendre, écrire, arrêter, suivre les sessions extérieures sans doublon, ce que l'île montre (au travail, en attente, terminé pendant 8 s), `nextDeadline`.

Tests : 29, avec un faux agent ACP (en mémoire et en vrai processus). **Essai en vrai** (`tool/smoke.dart`) : adaptateurs installés dans le dossier de Mikky sous Windows et dans WSL, les quatre connexions vues, 13 + 7 sessions du dernier jour trouvées, un Claude dans WSL (passé sur Sonnet) et un Codex sous Windows lancés, « ok » tous les deux, sans doublon, événements de la sonde WSL reçus, plus aucun processus ensuite.

Pas fait, noté pour plus tard : le secours en ligne de commande (spec §3.2 ; ACP a marché partout) ; un Node privé sous Windows si celui du système manque ou est trop vieux (aujourd'hui : message « Node manquant ») ; la connexion essayée en vrai (les quatre étaient déjà connectées ; seule la lecture du lien et du code est testée) .

Prévu : Client ACP ; lancement Windows / WSL et arrêt ; secours CLI ; installation des adaptateurs dans le dossier de Mikky ; connexion (`claude auth status`, `codex login status`, device auth, `claude auth login`) ; surveillance des sessions extérieures (+ sonde WSL si besoin) ; `RealAgentSource` ; `%APPDATA%\Mikky\agents.json`. Tests avec un faux agent ACP qui rejoue un enregistrement.

## A3 · Composants en Flutter (`app/lib/ui/`)

**Fait (2026-09-29), à valider par l'utilisateur.** `tokens.dart` (jetons clair / sombre de `mikky-ui.css`, ombres CSS telles quelles), `surface.dart` (forme peinte comme le CSS : ombres dehors, dégradé, ombres intérieures), `icons.dart` (les icônes SVG des maquettes, lues telles quelles), `motion.dart` (appui, ressorts, « moins d'animations »), `buttons.dart`, `selectors.dart` (sélecteur à capsule en ressort 420 / 0,78 qui s'étire, interrupteur, pastilles), `field.dart` (champ de recherche, le « Champ » qui grandit jusqu'à 5 lignes avec ses options à moitié dedans, Entrée envoie), `feedback.dart` (états d'un agent animés, notification, progression, badges, points), `cards.dart` (carte d'agent, en-tête de groupe, Oui / Non, carte de tâche), `thread.dart` (ligne de métro avec trait bleu et halo, bulles, code en direct), `side.dart` (cadre de la petite fenêtre, en-tête, Mikky en petit). Écran de contrôle : `mikky.exe --kit` (`kit_app.dart`). Goldens : `test/goldens/ui_kit_{light,dark}.png`, comparés aux captures de `composants.html` et `ux-a.html`. Pas repris : les écrans Partage / Mails de la planche (hors de l'UX retenue).

Retours de l'utilisateur (2026-09-29) et corrections :
- **Reflet clair en bas des sélecteurs** : l'ombre de la capsule était coupée par le cadre du sélecteur ; elle déborde maintenant comme en CSS.
- **Un peu plus gluant** : ressort 380 / 0,70 (au lieu de 420 / 0,78), étirement jusqu'à 12 px.
- **Barre d'onglets gardée** (pour plus tard) : `tabs.dart`, grande (givrée) et en icônes seules.
- **Lag des sélecteurs** : dans une zone qui défile, Flutter attendait ~100 ms (clic ou glissement ?) avant de réagir ; l'appui et le choix partent maintenant dès que le bouton descend (`Listener`).
- **Optimisation** (mesurée sur le kit, `mikky.exe --kit`, une planche) : Flutter redessine toute la fenêtre à chaque image (~6 ms de CPU), dès qu'une seule petite boucle tourne. Les boucles décoratives passent sur une horloge commune à 30 images/s (`DecorClock`), les gestes restent à 60 ; ombres intérieures floues dessinées une fois puis réutilisées ; pas de découpe sous les surfaces opaques ; pas de couche par bouton. **37 % → 17 % d'un cœur** (1,4 % sans animation). `mikky.exe --kit --perf` montre les temps d'image.

Jetons clair / sombre de `mikky-ui.css`, boutons (capsules, ronds, principal noir), sélecteur à capsule, interrupteur, champ (gris en creux, grandit jusqu'à 5 lignes, options à moitié dedans), cartes et en-têtes de groupe repliables, ligne de métro (trait bleu, halo lent), bulles de chat, menus, et le tableau des animations de `composants.html`. Goldens comparés aux captures de la planche (`#calme`, `#sombre`).

Bugs trouvés et corrigés : une attente circulaire (`whenComplete(() => map.remove(…))` renvoie le futur lui-même) bloquait tout lancement ; la session d'un agent dans WSL recevait le chemin vu de Windows au lieu du chemin Linux (Codex partait de `/tmp` et ses commandes échouaient) ; les pages ne prenaient que la hauteur de leur en-tête ; les étapes montraient des commandes entières au lieu de leur description ; le code sous l'étape en cours pouvait venir d'une étape précédente ; Markdown des réponses affiché brut ; commandes longues coupées sur la carte en attente.

**Fait ensuite (même jour)** :
